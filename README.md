# CloudSun Dental

> The AI-powered front desk for modern dental practices.

CloudSun Dental handles new-patient enquiries, appointment requests, missed calls, cancellations, recalls and treatment follow-up — while your team stays in control.

**Repository:** [hello-aditya-dev/cloudsun](https://github.com/hello-aditya-dev/cloudsun)

**Current state:** Interactive product prototype. All features are simulated. No real patient data. No production integrations connected. No healthcare compliance certifications.

---

## Dental product overview

CloudSun Dental is designed for:

- Independent dental practices
- Multi-dentist practices
- Dental groups and DSOs
- Orthodontic practices
- Cosmetic dentistry practices
- Implant and specialist clinics

The product handles:

- New-patient enquiry capture and booking
- After-hours and missed-call coverage
- Cancellation recovery with waitlist matching
- Patient recall and reactivation
- Unfinished treatment follow-up
- Emergency screening with red-flag escalation
- Clinical-question handoff (never diagnoses)
- Multi-location practice management

## Current prototype status

CloudSun Dental is an interactive product prototype. Every feature is simulated:

- **AI responses** are generated by a deterministic simulation engine — no real AI model is called
- **Telephony** uses demo telephony — no Twilio connected
- **Email, WhatsApp, calendar** use typed mock adapters — providers not connected
- **Authentication** enters the demo workspace without verifying credentials
- **Payment processing** is disabled
- **All patient data** is fictional (Lumen Dental Care — 3 locations, 42 patients)

Production healthcare deployments would require technical, contractual and legal controls appropriate to the customer's jurisdiction and systems.

## Dental modules

### Recall (`/app/recall`)

- Patient groups: Due now, Due in 30 days, Overdue 30+, Overdue 60+, Overdue 90+, Contacted, Responded, Booked, Declined, Do not contact
- Bulk selection and simulated reminder sending
- Recall sequence builder (initial → follow-up → alternative channel → human call → close)
- All actions persist via `RecallRepository`
- All outreach is simulated — no real patients contacted

### Waitlist & Cancellation Recovery (`/app/waitlist`)

- Open slot display with location, provider, type, value
- Waitlist patient ranking with match reasons
- Complete workflow: cancellation → rank → approve → invite → accept → fill slot → stop remaining
- All actions persist via `WaitlistRepository`
- Acceptance creates appointment in demo repository

### Treatment Follow-up (`/app/treatment-follow-up`)

- 9-stage pipeline: follow-up due → first message → patient responded → question pending → coordinator required → appointment booked → not ready → declined → closed
- Guardrails: no diagnosis, no pressure, no invented prices, respect consent and do-not-contact
- All actions persist via `TreatmentFollowUpRepository`

### AI Front Desk Builder (`/app/ai-agent`)

- Dental-specific identity configuration
- Emergency red-flag configuration (severe swelling, breathing difficulty, uncontrolled bleeding, major trauma, loss of consciousness)
- Clinical-question handoff rules (never diagnoses)
- Dental tool permissions (read availability, create appointment request, book, reschedule, cancel, add to waitlist, send confirmation, create lead, start recall, start treatment follow-up, transfer to human)
- Test playground with dental intent detection
- All settings persist via `AIConfigRepository`

## Dental safety rules

### Emergency red flags

The AI screens for the following before proceeding with any booking:

- Difficulty breathing
- Uncontrolled bleeding
- Severe facial swelling
- Major facial trauma
- Loss of consciousness
- Suspected medical emergency

If any red flag is detected, the AI:
1. Stops the normal booking workflow
2. Displays urgent escalation language
3. Advises contacting emergency services
4. Notifies a human in simulation

### Clinical-question handoff

The AI **never diagnoses conditions**. Clinical questions (e.g., "What's causing my tooth pain?", "Is it a cavity?", "Do I need a root canal?") always trigger human handoff.

### Disclaimer

> CloudSun Dental is a front-desk communication system. It does not diagnose conditions or replace clinical judgement.

- Waitlist acceptance states
- Treatment follow-up stage transitions
- AI configuration (draft and published)
- Integration demo connection status
- Automation enabled state
- Audit log entries

A **Reset demonstration workspace** action is available in Settings.

## Installation

### Prerequisites

- Node.js 18+ or Bun
- A terminal (PowerShell 5.1 on Windows, any shell on macOS / Linux)

### Install and run

```bash
git clone https://github.com/hello-aditya-dev/cloudsun.git
cd cloudsun
bun install
cp .env.example .env
bun run dev
```

### Windows PowerShell 5.1

```powershell
git clone https://github.com/hello-aditya-dev/cloudsun.git
cd cloudsun
bun install
Copy-Item .env.example .env
bun run dev
```

## Architecture

- **Framework:** Next.js 16 with App Router
- **Language:** TypeScript (strict mode)
- **Styling:** Tailwind CSS 4 with shadcn/ui
- **Motion:** Motion for React (central motion system in `src/lib/motion/`)
- **State:** localStorage-backed demo store with repository interfaces
- **Database:** Prisma ORM (PostgreSQL target schema, not required for demo)
- **Tests:** Vitest (unit), Playwright (e2e)
