=== PAGE 1 ===
CLOUDSUN — PREMIUM MOTION, ANIMATION
AND INTERACTION OVERHAUL
You are working inside the existing CloudSun repository:
https://github.com/hello-aditya-dev/cloudsun
Live deployment:
https://cloudsun-aditya.vercel.app/
CloudSun is an omnichannel AI front desk and client inbox for phone calls, email, WhatsApp, website
chat and appointment scheduling.
The website and dashboard are visually strong, but they currently feel too static.
Your task is to create a complete, production-quality motion system across the marketing website,
onboarding experience and application dashboard.
Do not redesign the website.
Do not change the brand.
Do not rewrite the content.
Do not change the product architecture unless a small structural change is necessary for correct
animation.
Do not add random animations to every element.
The objective is to make CloudSun feel:
Alive.
Responsive.
Premium.
Intelligent.
Calm.
Highly polished.
Deliberate.
Comparable to a high-end SaaS product designed by an elite product studio.
The result must feel more expensive without becoming flashy, distracting or slow.

Do not maintain both framer-motion and motion unless an existing dependency genuinely
requires the old package.
If the project does not use framer-motion directly after migration:
bunremoveframer-motion
Do not install multiple animation libraries that perform the same job.
Use:
Motion for React for stateful, layout, gesture, presence and scroll animation.
CSS transitions for simple colour and border changes.
CSS keyframes only for tiny, self-contained decorative loops.
The Web Animations API only where Motion is unnecessary.
Do not add GSAP unless there is a specific animation that Motion cannot implement cleanly.

=== PAGE 6 ===
A. Reveal
For content entering the viewport:
Opacity from 0 to 1.
Vertical offset between 12px and 28px.
Optional very subtle blur from 4px to 0.
Duration between 0.45 and 0.65 seconds.
Stagger between 50ms and 90ms.
Run once for normal marketing sections.
Do not make every paragraph independently animate.
Animate logical content groups.
B. Reflow
For filters, tabs, cards, panels and changing data:
Use layout.
Use layoutId.
Use LayoutGroup.
Preserve spatial continuity.
Avoid elements suddenly teleporting.
C. Presence
For drawers, modals, menus, context panels and conditional content:
Use AnimatePresence.
Animate both entrance and exit.
Keep exit animation short.
Do not leave invisible elements blocking pointer input.
D. Feedback
For hover , tap, selection, success and loading:
Buttons depress slightly on tap.
Cards lift subtly on hover .
Selected navigation indicators glide.
Success states confirm actions.
Loading states feel responsive.
Avoid constant pulsing where no action is occurring.

39. PERFORMANCE REQUIREMENTS
Animation must improve perceived quality without degrading performance.
Requirements:
Prefer transform and opacity.
Avoid frequent layout-triggering property animation.
Use Motion layout animation for measured reflow.
Avoid animating large blurred layers continuously.
Avoid large full-screen filters.
Pause offscreen loops.
Pause hidden-tab animations.
Do not attach one scroll listener per card.
Avoid unnecessary React state updates every animation frame.
Use Motion values for frame-sensitive animation.
Use LazyMotion.
Lazy-load heavy demonstration sections.
Memoize expensive static visual components only where measurements show benefit.
Prevent unnecessary list re-renders in inbox and calls.
Avoid introducing hydration errors.
Avoid cumulative layout shift.
Maintain smooth scrolling.
Do not use JavaScript intervals for simple continuous animation when Motion or CSS can handle it.
40. MOBILE MOTION
Mobile motion must not simply copy desktop motion.
Requirements:
Shorter durations.
Smaller distances.
No hover assumptions.
No cursor effects.
Drawers should feel touch-native.
Bottom navigation indicator should glide.
Full-screen conversation transitions should reflect forward and backward navigation.
Keep keyboard and composer behaviour stable.
Do not animate elements beneath the software keyboard.
